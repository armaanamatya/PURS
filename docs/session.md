Output store for per-question attention analysis from benchmark runs. Structure:
```
vizzing/all/{viz_type}/{dataset}/{task_type}/q{NNN}/
    1_crossmodal_attention_curves.png
    2_self_vs_cross_attention.png
    3_attention_gini_depth.png

    5_last_token_attention_depth.png
    meta.json      # dataset, task_type, duration, answer
    question.txt   # the MC question
    run.log

```

Generated by `viz_attention_depth_curve.py` and `viz_attention_encoders.py` via the orchestration runner `scripts/run_all_attention_viz.py`, which calls them with `--video_path`, `--question`, `--out_dir` per benchmark question.

## 3. Architecture — Full Pipeline

```
Video/Audio file
    │
    ├─ Audio Encoder (32 Whisper-style layers)
    │       → audio_features: (T_audio, 3584)       ← projected to LLM dim
    │       → attn_logits: (H, T_audio, T_audio)    ← last encoder layer self-attn
    │                                                   CAPTURED HERE for OmniZip scoring
    │
    └─ Vision Encoder (32 ViT-style blocks)
            → video_features: (T_video, 3584)        ← projected to LLM dim

Step 1: inputs_embeds = embedding_table(input_ids)          # (1, L, 3584) — placeholders for A/V
Step 2: inputs_embeds[audio_positions] = audio_features     # overwrite with real audio
        inputs_embeds[video_positions] = video_features     # overwrite with real video
        ← EMBED SPACE: (1, L, 3584) fully assembled, NO LLM layers run yet

Step 3: omnizip(inputs_embeds, attn_logits, ...)            # optional compression
        → scores + drops audio rows from the matrix
        → scores + drops video rows
        → merges some dropped tokens into kept ones (weighted average)
        → returns inputs_embeds[:, global_mask, :]          # (1, compressed_len, 3584)

Step 4: Thinker LLM 28 decoder layers run on compressed inputs_embeds
```

**No pruning happens in the encoders.** Both encoders run fully. OmniZip only reads the audio encoder's last-layer attention as a scoring signal; the encoders themselves are untouched.

## 4. OmniZip Internals — What `omnizip()` Actually Does

All four steps happen inside one function call (`omnizip_units.omnizip`), entirely in embed space (step 3 above). The monkey-patch in viz scripts intercepts this single function to capture `global_mask`.

### Step 1 — Audio token scoring
- Source signal: `attn_logits [H, T_audio, T_audio]` = audio encoder last-layer **intra-audio self-attention** (NOT cross-modal)
- Importance score: `attn_logits.mean(dim=0).sum(dim=0)` = column sum after averaging heads = "how much do all other audio tokens attend to this one" = hub centrality
- Action: topk by importance, keep `(1 - rho_audio) × T_audio` tokens

### Step 2 — Video pruning (audio-guided indirectly)
- Audio retention rate per temporal group is computed from step 1's output
- Groups where audio kept more → more audio is salient there → lower video drop ratio in that time window
- This is the "audio-guided" part — **not direct cross-attention, but budget allocation**
- Within each group, video selection is done by `omnizip_istm`:
  - **Even frames**: DPC-KNN — keeps spatially diverse patches (density-peak clustering)
  - **Odd frames**: cosine similarity with previous frame → keeps most-different tokens (temporal change detection)
  - No audio content used at this stage

### Step 3 — Token merging (the `g=3` parameter)
- Dropped audio tokens are NOT simply deleted — they can be merged into kept "anchor" tokens
- Merge weights use audio↔video cosine similarity in embed space: `a_norm[dropped] @ v_norm.T`
- Audio tokens geometrically close to video tokens in 3584-dim space get higher merge weight
- Result: anchor token = weighted average of itself + nearby dropped tokens
- This is the only place direct audio↔video interaction occurs in OmniZip

### Step 4 — Contextual preservation (`contextual_ratio=0.05`)
- Evenly-spaced sample of otherwise-pruned tokens kept to maintain broad coverage

### `global_mask` output
- Shape: `(orig_seq_len,)` bool — True = token survived
- **Does not distinguish** which step caused each decision
- Why viz scripts only see a single flat mask

## 5. Where Each Viz Script Gets Its Data

### `viz_attention_qwen.py` / `viz_attention_omnizip.py`
- Run `model.thinker(output_attentions=True)` → get `output.attentions` tuple of 28 tensors `(1, heads, seq, seq)`
- Sample 3 layers: 0, 13, 27
- Look at row `seq_len - 1` (last prompt token) averaged over heads
- Classify by `audio_token_id` / `video_token_id` positions in `input_ids`
- OmniZip version additionally captures `global_mask` via monkey-patch and remaps all positions through `orig_to_comp`

### `viz_attention_heatmap_qwen.py` / `viz_attention_heatmap_omnizip.py`
- Same forward pass but take the **full (seq, seq) matrix** at chosen layers
- Additionally call `model.thinker.get_rope_index(...)` to get temporal position IDs per token
- Discretize into time windows: `window_id = (temporal_pos - ref) // (position_id_per_seconds × seconds_per_chunk)`
- Pick inset window = highest `0.5 × (mean(audio→video) + mean(video→audio))` score

### `viz_attention_depth_curve.py`
- Uses **forward hooks** on all 28 `layer.self_attn` modules instead of `output_attentions=True`
- Streams compact statistics per layer and immediately drops the full attention matrix → memory efficient
- Captures: cross-modal attention pairs, Gini coefficients, last-token modality distribution

### `viz_attention_encoders.py`
- Hooks **Q and K projections** inside audio encoder (`Qwen2_5OmniAudioAttention`) and vision encoder (`Qwen2_5OmniVisionAttention`) — the encoders don't expose attention weights natively
- Manually computes `softmax(Q @ K^T / sqrt(d))` from intercepted projections

## 6. Two Unexplored Approaches (Question-Conditioned Pruning)

OmniZip's core limitation: **it is question-blind**. The same video gets the same tokens dropped regardless of what is asked. These two approaches would fix that.

### Approach A — Embed space cosine similarity (zero extra cost)

Insert between Step 2 and Step 3 (after encoders write into `inputs_embeds`, before OmniZip):

```python
text_rows  = inputs_embeds[0, text_positions]    # (T_text,  3584)
audio_rows = inputs_embeds[0, audio_positions]   # (T_audio, 3584)
video_rows = inputs_embeds[0, video_positions]   # (T_video, 3584)

t = F.normalize(text_rows,  dim=-1)
a = F.normalize(audio_rows, dim=-1)
v = F.normalize(video_rows, dim=-1)

audio_relevance = (a @ t.T).max(dim=1).values   # (T_audio,) — per audio token
video_relevance = (v @ t.T).max(dim=1).values   # (T_video,) — per video token
```

Cost: two matrix multiplications — negligible. No encoder reruns, no LLM layers.
Gives: "which audio/video tokens are geometrically closest to question tokens in 3584-dim space"
Could replace or augment the intra-audio importance score inside `omnizip_audio_attn`.

Caveat: LLM embedding space is not isotropic — cosine similarity there can be noisy since the embedding table isn't trained for this kind of lookup.

### Approach B — Early Thinker layer attention hook (1–4 layers of cost)

Hook the first 1–4 decoder layers, extract text→audio/video attention, then stop before full 28-layer forward:

```python
def hook(module, args, kwargs, output):
    attn = output[1]   # (1, heads, seq, seq) — eager mode only
    # How much do text queries attend to audio keys at this layer?
    score = attn[0, :, text_positions, :][:, :, audio_positions].mean(dim=(0,2))
    # → (T_audio,) per-token relevance from the LLM's own first-pass attention
```

Cost: ~1/28th of full prefill per layer used. Stopping at layer 1–2 is very cheap.
Gives: relevance grounded in the LLM's **learned Q/K projections** — more reliable than raw cosine in embed space because it captures what the model actually "looks for."
Strongest use: use layer 0–2 attention to score tokens, feed those scores into OmniZip instead of encoder-derived scores, then run the compressed sequence through all 28 layers.

## 7. Key Facts to Remember

- **Embed space** = the `(B, L, 3584)` matrix sitting between encoders and LLM transformer layers. Accessible before any decoder layer runs.
- **Audio and video tokens have identical dimensions** (3584) in embed space — both projected there.
- **OmniZip's only cross-modal signal** is cosine similarity between audio and video in embed space, used only for merge weighting (step 3), not for primary scoring.
- **`attn_logits`** passed into OmniZip = intra-audio self-attention from audio encoder last layer. Not cross-modal. Not question-aware.
- **`global_mask`** is a flat boolean — doesn't record which of the 4 steps caused each drop.
- The heatmap scripts (`viz_attention_heatmap_*.py`) have **never been run** — no output directories exist.
- `viz_attention_depth_curve.py` uses hooks (not `output_attentions=True`) to avoid holding 28 full attention matrices in memory simultaneously.
